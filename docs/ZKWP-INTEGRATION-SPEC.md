# Интеграция с базами ZKwP (чипы + питомники)

Статус: **блок A реализован** (2026-08-20) — шаги 0–5 плана выполнены; found-фикстура
синтетическая (реальный чип зарегистрированной собаки не добыт — парсер с
rawText-фолбэком, см. §3.2). Блок B (przydomki) не начат.
Дата: 2026-08-20.

## 1. Зачем

Сейчас проверка микрочипа в объявлении — только формат (ISO 11784/85) и уникальность
внутри нашей базы (`listing.validation.ts`). Публичная «Baza chipów» ZKwP
(https://zkwp.pl/baza_chip.php) позволяет проверить, что чип принадлежит собаке,
которой отделение ZKwP реально выдало metrykę, — то есть **подтвердить породистость
собаки по внешнему авторитетному источнику**. Это:

- усиливает ключевую ценность продукта (верификация) реальной, а не только форматной проверкой;
- даёт админу при модерации данные для сверки (кличка, przydomek, пол, дата рождения, oddział);
- превращается в публичный маркер «Zweryfikowano w bazie ZKwP» — витрина уникальности.

Дополнительно (низший приоритет): проверка приставки питомника (przydomek hodowlany)
по реестрам ZKwP/FCI при верификации заводчика.

## 2. Разведанные факты (проверено вживую 2026-08-20)

### 2.1 Baza chipów ZKwP — `https://zkwp.pl/baza_chip.php`

- Форма: `POST` на тот же URL, единственное поле `chip` (15 цифр). Без captcha,
  без cookies/токенов, без авторизации.
- Ответ — та же HTML-страница; при неудаче в блок результата добавляется строка:
  `<b><font color=#FF0000>Podany numer jest błędny lub nie jest zarejestrowany w bazie ZKwP.</font></b>`
- По описанию на странице, при успехе возвращаются: **nazwa (кличка), przydomek
  hodowlany, płeć, data urodzenia, oddział ZKwP** (выдавший metrykę; для импортов —
  oddział ностряфикации).
- ⚠️ **Разметка положительного ответа не разведана** — для этого нужен чип реально
  зарегистрированной собаки. См. §5 шаг 0 и защитный парсер в §3.2.
- База содержит собак с выданными metryki + импортированных/ностряфицированных.
  Следствие: **«не найден» — нейтральный сигнал** (щенок мог ещё не попасть в базу),
  **«найден» — сильный позитивный** (собака зарегистрирована в ZKwP).

### 2.2 Przydomki ZKwP — `https://zkwp.pl/przydomki_szukaj.php`

- `GET ?pfind=<текст>&szukaj=Szukaj`, без captcha. Ответ — HTML-таблица со списком
  приставок, совпадения обёрнуты в `<b class=text-success>`. Подстрочный поиск
  (по фрагменту), регистронезависимый.
- Это список приставок «zarejestrowane tylko w ZKwP bez rejestracji w FCI»;
  FCI-приставки — отдельный реестр http://www.fci.be/en/affixes/ (ASP.NET + VIEWSTATE,
  скрейпить сложнее; есть autocomplete-сервис `GetCompletionList` на
  `/affixes/default.aspx`). Полная проверка = ZKwP-список ∪ FCI-реестр.

### 2.3 Чего нет

- Официального API нет ни у ZKwP, ни у Safe-Animal/Europetnet/CBDZOE — только веб-формы.
- Публичной проверки номера родословной (PKR) онлайн нет — родословная остаётся
  «формат + ручная модерация» (как в VERIFICATION-STRATEGY.md).

## 3. Дизайн решения

### 3.1 Принципы

1. **Best-effort, никогда не блокирует.** Недоступность/изменение разметки zkwp.pl
   не должны мешать создать или отправить объявление. Любая ошибка → статус
   `unavailable`, поведение системы деградирует до текущего.
2. **Асимметричная трактовка.** `found` — сильный позитив (зелёный + печать);
   `not_found` — нейтрально-жёлтая подсказка админу, НЕ красная ошибка;
   `unavailable` — серое «не удалось проверить».
3. **Публично показываем только факт** («Zweryfikowano w bazie ZKwP»), возвращённые
   данные (кличка, przydomek, oddział) — только админу в очереди модерации.
4. **Щадящий трафик.** Запрос только в моменты отправки на модерацию (редкое
   событие), результат кэшируется в документе объявления; повторный запрос — только
   если изменился номер чипа. Таймаут 5 с, 1 повтор, свой User-Agent
   `PedigreeHub/1.0 (weryfikacja mikroczipow; kontakt: <email>)`.

### 3.2 Backend: `src/services/zkwp.service.ts`

Синглтон-класс по образцу `nip.service.ts`:

```ts
export type ZkwpChipStatus = 'found' | 'not_found' | 'unavailable'

export interface ZkwpChipResult {
  status: ZkwpChipStatus
  dog?: {
    name?: string          // kличка
    kennelName?: string    // przydomek hodowlany
    sex?: string           // 'pies' | 'suka' — как отдаёт сайт, без нормализации
    birthDate?: string     // строкой, как отдаёт сайт (формат неизвестен до разведки)
    branch?: string        // oddział ZKwP
    rawText?: string       // фолбэк: текст блока результата, если структуру не распознали
  }
  error?: string           // для unavailable — причина (таймаут/HTTP/парсинг)
}

class ZkwpService {
  async checkMicrochip(chip: string): Promise<ZkwpChipResult>
}
export const zkwpService = new ZkwpService()
```

Логика `checkMicrochip`:
1. Нормализация: убрать пробелы/дефисы; если не `/^\d{15}$/` → сразу `not_found`
   (не тратим запрос — формат и так проверяет `validateMicrochipFormat`).
2. `fetch('https://zkwp.pl/baza_chip.php', { method: 'POST', body: 'chip=...',
   headers: { 'Content-Type': 'application/x-www-form-urlencoded' } })`,
   AbortController 5 с, 1 ретрай при сетевой ошибке.
3. Парсинг (**защитный, трёхступенчатый** — потому что положительная разметка не разведана):
   - в HTML есть `nie jest zarejestrowany w bazie ZKwP` → `not_found`;
   - иначе вырезать блок результата (фрагмент между формой и следующей секцией,
     см. фикстуры), распознать пары «метка: значение» / таблицу → `found` + поля;
   - блок есть, но структура не распозналась → `found` c `dog.rawText`
     (plain-text блока, теги вырезаны, ≤ 500 символов) — админ всё равно увидит данные.
   - HTTP ≠ 200 / таймаут / пустой ответ → `unavailable`.
4. Никогда не бросает — все ошибки в `status: 'unavailable'`.

Тесты сервиса — на HTML-фикстурах (`src/services/__fixtures__/zkwp/*.html`),
fetch мокается; живой сайт в тестах не дёргаем.

### 3.3 Модель: `autoChecks.zkwpChip`

В `listing.model.ts` (и интерфейс `IListing`) внутрь `autoChecks` добавляется:

```ts
zkwpChip?: {
  status: 'found' | 'not_found' | 'unavailable'
  dogName?: string
  kennelName?: string
  sex?: string
  birthDate?: string
  branch?: string
  rawText?: string
  birthDateMatches?: boolean   // только если удалось распарсить дату и сравнить
  checkedAt: Date
  checkedChip: string          // для какого номера получен результат (кэш-ключ)
}
```

Существующие boolean-поля `autoChecks` не меняются (обратная совместимость:
старые объявления просто не имеют `zkwpChip`).

`birthDateMatches`: если `birthDate` из ответа парсится как дата — сравнить с
`listing.birthDate` (по дню, таймзоны игнорируем). Не парсится → поле не ставим.

### 3.4 Точки вызова (listing.service.ts)

Вызов **не** внутри `validateListingData` (она отвечает за блокирующую валидацию),
а рядом, в сервисе, после успешной валидации:

1. `create(...)` при `params.status === 'pending'` (создание сразу на модерацию);
2. `updateStatus(...)` при переходе в `pending` (после полной валидации, там где
   сейчас пересобираются «свежие autoChecks для модератора»).

Кэш: если у объявления уже есть `autoChecks.zkwpChip` с
`checkedChip === microchipNumber` и `status === 'found'` — не перезапрашивать
(повторная отправка после reject с тем же чипом). `not_found`/`unavailable`
перепроверяем при каждой отправке (собака могла появиться в базе).

Черновики (`draft`) базу ZKwP не дёргают.

### 3.5 Админ-UI (AdminListingPreview.tsx)

В секцию autoChecks добавить блок «Baza ZKwP» (стиль — существующие строки чеков
+ mono-подписи из дизайн-системы, без hex — семантические токены):

- `found`: зелёный чек «Mikroczip znaleziony w bazie ZKwP» + под ним mono-строки:
  kличка, przydomek, płeć, data urodzenia, oddział (или `rawText`, если только он).
  Если `birthDateMatches === false` — янтарное предупреждение
  «Data urodzenia w bazie ZKwP różni się od podanej w ogłoszeniu».
- `not_found`: янтарная (не красная!) строка «Nie znaleziono w bazie ZKwP —
  szczenię mogło nie zostać jeszcze zarejestrowane. Zweryfikuj metrykę ręcznie.»
- `unavailable`: серая строка «Baza ZKwP była niedostępna podczas sprawdzania».
- Поля нет (старые объявления): блок не показывается.

Типы: `frontend/src/modules/admin/types/index.ts` → расширить `autoChecks`.

### 3.6 Публичный бейдж (PuppyPage)

Только при `autoChecks.zkwpChip.status === 'found'`:

- В паспортном блоке щенка — печать/пилюля «✓ Zweryfikowano w bazie ZKwP»
  (мотив круглой печати из дизайн-направления «документальный премиум»;
  labelMono, без раскрытия данных из базы).
- В `getPublicListings`/`getById` для публичной выдачи наружу отдаётся **только**
  производный флаг (например, `zkwpVerified: true`), а не объект `zkwpChip` —
  чтобы не течь данными и структурой autoChecks. Полный `autoChecks` — только
  админ-роуты (как сейчас).
- ⚠️ Флаг ставится, только если ответ базы распознан **полями** (кличка/przydomek/
  płeć/дата/oddział). `found`, полученный по одному `rawText`-фолбэку, админ видит
  (янтарная строка «Odpowiedź bazy ZKwP nierozpoznana»), но публичной верификацией
  он не становится: иначе смена вёрстки или текста ошибки на zkwp.pl превратилась бы
  в ложные публичные «Zweryfikowano». Дополнительная страховка — набор маркеров
  «нет в базе» (`NOT_FOUND_MARKERS`), покрывающий переформулировки сообщения.
- Упоминание в блоке «Jak weryfikujemy» на главной: пункт про базу ZKwP.

### 3.7 Блок B (опционально, после блока A): приставка питомника

- `zkwp.service.ts` → `searchKennelName(name: string)`: GET `przydomki_szukaj.php`,
  парсинг `<b class=text-success>`-совпадений, возврат списка точных/частичных
  совпадений (сравнение без диакритики и регистра).
- Вызов при подаче заявки на верификацию заводчика (рядом с NIP-проверкой);
  результат — в `breeder.verification` (например, `zkwpKennelCheck: { status:
  'exact' | 'partial' | 'not_found' | 'unavailable', matches: string[], checkedAt }`).
- В админ-очереди заводчиков — строка-подсказка (те же три цвета).
- FCI-реестр в v1 не трогаем (ASP.NET/VIEWSTATE; отсутствие в ZKwP-списке не
  значит отсутствие в FCI — поэтому `not_found` здесь тем более нейтральный).

## 4. Риски и допущения

| Риск | Митигция |
|---|---|
| Разметка положительного ответа неизвестна | Шаг 0 разведки (§5); трёхступенчатый парсер с `rawText`-фолбэком; при полном провале — `unavailable` |
| zkwp.pl изменит HTML | Ошибка парсинга → `unavailable`, система деградирует до текущего поведения; фикстурные тесты ловят регрессию при обновлении фикстур |
| zkwp.pl заблокирует/ограничит запросы | Запросы только при отправке на модерацию + кэш `found`; честный User-Agent с контактом; таймаут и 1 ретрай |
| Кодировка (латиница с диакритикой в кличках) | Читать `Content-Type`/meta charset фикстур, при необходимости декодировать ISO-8859-2 → проверяется на шаге 0 |
| Юридически: скрейпинг | Публичная поисковая форма, прямо предназначенная для проверки собак посторонними; объёмы — единичные запросы; данные наружу не републикуем (публично — только флаг) |
| «found» по чипу чужой собаки (заводчик вписал чужой чип) | Уникальность чипа в нашей базе уже проверяется; админ сверяет kличку/дату/oddział с документами — данные для этого теперь на экране |

## 5. План реализации (блок A ≈ 0.5–1 день)

0. **Разведка положительного ответа.** Найти чип реально зарегистрированной
   собаки (объявления заводчиков ZKwP, выставочные каталоги; в крайнем случае —
   попросить пользователя спросить у знакомого владельца родословной собаки).
   Снять HTML-фикстуры: found / not_found / (искусственно) обрыв. Если чип найти
   не удалось — реализуем по «not_found + фолбэк rawText», найденный кейс
   докручиваем позже; это не блокер.
1. **`zkwp.service.ts` + фикстуры + vitest-юниты** (парсер, таймаут, ретрай, никогда-не-throw).
2. **Модель + точки вызова**: `autoChecks.zkwpChip` в `listing.model.ts`,
   вызовы в `create`/`updateStatus`, кэш по `checkedChip`, `birthDateMatches`.
   Интеграционные vitest: сабмит на модерацию сохраняет `zkwpChip` (fetch мокнут).
3. **Админ-UI**: блок «Baza ZKwP» в AdminListingPreview + типы. Playwright-прогон
   админ-очереди на 1440/390 со скриншотами (сид-объявление с мокнутым результатом
   или реальным чипом из шага 0).
4. **Публичный бейдж**: флаг `zkwpVerified` в публичной выдаче, печать на PuppyPage,
   пункт в «Jak weryfikujemy». Playwright + скриншоты.
5. **Документация**: обновить `docs/VERIFICATION-STRATEGY.md` (раздел «внешние
   проверки»), Swagger-схемы ответов затронутых эндпоинтов.

Блок B (приставки, ≈ 0.5 дня) — отдельным этапом после приёмки блока A.

## 6. Вне скоупа v1

- Live-проверка чипа в визарде создания объявления (эндпоинт для заводчика) —
  лишний трафик на zkwp.pl и подсказка для перебора; админ-модерации достаточно.
- Кнопка «Sprawdź ponownie» в админке — добавим, если админ-флоу это попросит.
- FCI affixes, Europetnet/Safe-Animal — нет API, ценность ниже (не подтверждают породистость).
- Периодическая ре-верификация уже опубликованных объявлений.
