# Разделение работы между разработчиками

## Обзор

Проект разделён между двумя разработчиками по функциональному принципу:
- **Разработчик 1:** Публичная часть + Аутентификация
- **Разработчик 2:** Панели управления + Админка

---

## Разработчик 1: Публичная часть + Auth

### Backend задачи

| Модуль | Задачи | Сложность |
|--------|--------|-----------|
| **Настройка** | Express.js, MongoDB, структура проекта | ⭐⭐ |
| **auth** | JWT, регистрация, логин, восстановление пароля | ⭐⭐⭐ |
| **users** | CRUD пользователей, профили | ⭐⭐ |
| **breeds** | Справочник пород (CRUD) | ⭐ |
| **breeders** | Публичные профили заводчиков (GET) | ⭐⭐ |
| **listings** | GET запросы, фильтрация, поиск | ⭐⭐⭐ |
| **reviews** | GET запросы (отзывы заводчика) | ⭐ |

### Frontend задачи

| Модуль | Компоненты | Сложность |
|--------|------------|-----------|
| **Настройка** | Vite, Chakra UI, React Query, роутинг | ⭐⭐ |
| **auth** | LoginPage, RegisterPage, ForgotPassword | ⭐⭐ |
| **shared/ui** | FormInput, FormSelect, Pagination, Badge | ⭐⭐ |

### Примерный объём работы

**Backend:** ~30% кодовой базы

**Итого:** ~45% проекта

## Точки синхронизации

### 1. API Контракты (Неделя 1)

Перед началом работы согласовать:
- Формат запросов/ответов
- Коды ошибок
- Названия эндпоинтов
- Структуру JWT токена

### 2. Интеграция Auth (Неделя 2)

Разработчик 2 зависит от готового auth модуля:
- Middleware аутентификации
- Роли пользователей
- Защита роутов

### 3. Listings API (Неделя 3-4)

Синхронизация:
- Разработчик 1: GET эндпоинты, фильтрация
- Разработчик 2: POST/PATCH/DELETE
- Общая модель данных Listing

### 4. Frontend интеграция (Неделя 5-6)

- Общие UI компоненты (shared/ui)
- API хуки
- Состояние авторизации (Zustand store)

## Инструменты совместной работы

### Git Flow

```
main ────────────────────────────────────────────►
  │
  └── develop ───────────────────────────────────►
         │                          │
         ├── feature/auth ──────────┤
         │                          │
         ├── feature/catalog ───────┤
         │                          │
         ├── feature/listings-crud ─┤
         │                          │
         └── feature/admin ─────────┘
```

### Правила веток

- `main` — production код
- `develop` — интеграционная ветка
- `feature/*` — фичи
- Pull Request для мержа в develop
- Code review обязателен

### Коммуникация

| Инструмент | Для чего |
|------------|----------|
| GitHub Projects | Задачи, kanban доска |
| Discord/Slack | Ежедневная коммуникация |
| GitHub Issues | Баги, вопросы |
| Figma | Макеты (опционально) |
